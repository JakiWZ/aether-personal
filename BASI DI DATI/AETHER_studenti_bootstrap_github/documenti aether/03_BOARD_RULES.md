# Regole della Scrum Board

## Stage

### Backlog
Richiesta conosciuta, ma non pronta per essere sviluppata.

### Ready
La Story rispetta la Definition of Ready ed è stata scelta per lo Sprint.

### In Progress
Qualcuno la sta sviluppando.

### Code Review
È presente una Pull Request e si attende revisione.

### Testing
La PR o la funzionalità è in verifica rispetto agli Acceptance Criteria.

### Done
Definition of Done completamente rispettata.

## Limiti WIP consigliati

Per ogni squadra:
- massimo 2 Story contemporaneamente in `In Progress`;
- prima di iniziare una terza Story, aiutare a chiuderne una.

## Story Points

Usare soltanto:
1, 2, 3, 5, 8

Se una Story viene stimata 13 o più, deve essere spezzata.

## Assegnazione

Le Issue non vengono pre-assegnate ai singoli studenti dal bootstrap.

Durante lo Sprint Planning:
1. la squadra sceglie la Story;
2. la Story viene spostata in Ready;
3. si creano eventuali Task tecnici;
4. gli studenti si auto-assegnano;
5. il team garantisce ownership collettiva.
